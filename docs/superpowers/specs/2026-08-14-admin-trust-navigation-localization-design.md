# 管理员信任状态、导航与中文化修复设计

## 背景

三角色浏览验收确认了三个主要问题：

1. 管理员通过审核后，房源已经是 `APPROVED` 并进入公开目录，但公开卡片和详情仍可能显示“待平台审核”。
2. 桌面端没有可发现的管理员入口，管理员必须预先知道 `/admin/trust` 与 `/admin/roommates` 路径。
3. 室友管理工作台的固定界面文案仍为英文，与其余中文产品界面不一致。

本次只修复以上三个问题。日期筛选、图片上传、在线申请、支付、托管、室友私信与组队确认仍按现有产品边界保持未开放。

## 目标与成功标准

- 所有通过公开房源接口返回的 `APPROVED` 房源，都明确带有“平台已审核”信任语义。
- 原始房东声明继续保留，不通过数据库迁移覆盖历史声明。
- 只有 `ADMIN` 用户能看到“房源审核”和“室友管理”两个直接入口。
- 两个管理员入口在桌面与移动布局中均可发现，并进入现有管理员路由。
- 室友管理页的固定标题、按钮、字段、状态、空态、权限门槛、成功提示和错误提示全部使用中文。
- 现有管理员二次验证、普通用户权限门槛和审核事务语义保持不变。

## 方案选择

采用“公开 API 规范化 + 条件管理员导航 + 静态文案中文化”的最小方案。

不采用纯前端覆盖，因为那会让 API 的 `status` 与 `trust` 继续互相矛盾，其他客户端仍可能显示错误。不采用数据库字段拆分和历史迁移，因为当前范围不需要重新设计信任模型，并且原始声明应保留作为审核上下文。

## 设计

### 1. 公开房源信任状态

`Listing.status` 是审核结果的权威来源，`Listing.trust` 保留发布者提交的声明与审核前文案。

`ListingsService.findAll` 和 `ListingsService.findOne` 在返回公开房源前生成公开展示值：

- 已包含“平台已审核”时保持不变；
- 包含“待平台审核”或“待审核”时替换为“平台已审核”；
- 只有其他声明时，在末尾追加“· 平台已审核”；
- 空声明时返回“平台已审核”。

该转换只作用于公开读取，不改写数据库记录。房东自己的房源列表和管理员待审队列继续取得原始声明，并用 `status` 展示各自的流程状态。

### 2. 管理员直接导航

现有主导航继续服务普通用户。应用识别到当前会话角色为 `ADMIN` 时，在顶部增加一个紧凑的“管理员工具”区域，包含：

- “房源审核” → `/admin/trust`
- “室友管理” → `/admin/roommates`

两个入口使用已有的路由与页面，不新增后台首页。普通用户、房东和未登录用户不渲染该区域。当前所在管理员页面对应入口显示选中状态。

管理员工具区域独立于主导航，避免在中等宽度下把六个主导航按钮挤在同一行；移动端仍直接显示两个管理员入口，不需要展开额外层级。

### 3. 室友管理中文化

只翻译产品界面的固定文案，不改写已有室友资料中的姓名、学校、职业、预算或通勤等用户数据。

中文化覆盖：

- 页面标题与说明；
- 刷新、新建、保存、归档按钮；
- 编辑器标题与全部字段标签；
- `active` / `hidden` 的展示文案；
- 加载、保存、归档成功提示；
- 加载、保存、归档失败提示；
- 未登录与非管理员权限门槛。

管理员二次验证触发条件和所有 API 调用保持原样。

## 数据流与错误处理

```text
管理员审核通过
  → 数据库 status = APPROVED，原 trust 保留
  → 公开读取根据 APPROVED 规范化 trust
  → 公开卡片与详情显示“平台已审核”

管理员会话 role = ADMIN
  → 顶部显示两个管理员入口
  → 进入现有审核或室友管理页面
  → 写操作继续要求管理员二次验证
```

本次不新增 API、不改变错误码、不放宽鉴权。公开信任值的规范化是纯展示转换，不会产生新的失败分支。

## 测试策略

严格采用测试先行：

1. 后端服务测试先证明公开列表与详情会把已审核房源规范为“平台已审核”，并证明原始模拟数据库记录未被修改。
2. 应用组件测试先证明管理员能看到并使用两个直达入口，普通用户看不到。
3. 室友管理组件测试先把操作文案和交互目标切换为中文，并覆盖中文加载、错误和权限提示。
4. 完成实现后运行相关测试、完整前端测试、API 测试、类型检查与构建。
5. 最后重新启动本地前后端，通过浏览器复查管理员审核后的公开卡片、管理员导航和室友管理中文界面。

## 非目标

- 不拆分或迁移 `trust` 数据库字段。
- 不修改管理员二次验证的 30 分钟有效期或权限规则。
- 不增加新的管理员首页、侧边栏或后台信息架构。
- 不实现当前标记为未开放的业务功能。
