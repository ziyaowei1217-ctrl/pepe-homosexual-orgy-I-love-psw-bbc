# 发布身份保存交接设计

## 背景

用户从“房东发布”进入发布页后，如果身份资料需要确认，会先看到“账户与资料”面板。资料保存请求已经成功，页面也会提示“资料已保存”，但发布页会继续强制展示身份面板，不会自动把用户带回发布表单，因此用户会误以为身份保存没有生效并卡在第一步。

根因有两部分：

1. 发布页将身份面板永久固定展示，即使当前资料已经满足发布条件。
2. 身份保存成功后只更新资料和提示文本，没有执行“关闭身份面板并继续发布”的完成态交接。

## 目标

- 在发布页保存完整且具备房东身份的资料后，自动进入房源发布表单。
- 用明确提示告诉用户身份已保存，可以继续发布。
- 保存失败或资料仍不满足发布条件时保留身份面板，并继续显示现有错误或补全要求。
- 不改变身份资料 API、发布 API、权限规则或房源字段。

## 交互设计

### 保存成功且具备发布权限

1. 服务端返回更新后的资料。
2. 前端更新本地资料状态并重新计算发布权限。
3. 如果发布权限为 `allowed`：
   - 清除发布身份引导原因；
   - 收起账户与资料面板；
   - 将视线带到发布房源流程顶部；
   - 显示“身份已保存，可以开始填写房源”。

### 保存成功但仍不具备发布权限

- 保留身份面板。
- 继续显示缺少资料或房东身份的现有门禁提示。
- 不渲染可提交的发布控件。

### 保存失败

- 保留身份面板和用户已填写的草稿。
- 显示接口返回的错误；没有具体错误时使用现有兜底文案。
- 不滚动到发布表单，也不改变发布权限。

## 状态与组件边界

- `SubletApp` 继续负责资料状态、发布权限和面板开关。
- 发布页只在以下任一条件成立时展示身份面板：
  - 用户主动打开账户面板；
  - 当前路径是账户页；
  - 发布权限尚未达到 `allowed`。
- `AuthFlowPanel` 继续负责表单提交和本地错误，不新增 API 调用。
- 发布流程增加稳定的页面锚点，仅供保存成功后的视线交接使用。

## 测试

- 组件回归测试：发布页的完整房东资料保存成功后，身份面板消失且发布表单可见。
- 门禁回归测试：资料仍不完整时身份面板保留，发布提交控件不可见。
- 失败回归测试：资料保存失败时身份面板保留。
- 浏览器验收：从房东发布进入，保存身份资料后自动看到发布流程第一步，并可继续到第二步。

## 非目标

- 本次不实现部分字段的远程草稿保存。
- 本次不调整发布流程后续步骤、图片上传方式或审核机制。
- 本次不重构认证与发布模块的整体结构。
