# 本次交接修复与验证

日期：2026-09-06。交付目标为可发送给他人查看和本地运行的源码 ZIP。

## 已修复的问题

1. 组合启动命令原来只运行 API、漏掉根目录前端；现在 `pnpm dev:local` 会同时启动两者。通过临时真实 pnpm 工作区先复现失败，再验证修复。
2. 本地 setup 原来只准备数据库；现在也启动 MinIO，并前台执行私有图片桶初始化，初始化失败会阻止后续步骤。
3. 生产 Docker 迁移命令原来指向不存在的根目录 Prisma 入口；现在使用镜像实际包含的 API 入口。容器中已应用全部 23 个迁移。
4. Docker 本地 API 使用 `db push`，不能可靠保留迁移中的自定义数据库约束；改为运行已提交的迁移，同时为 API 依赖增加独立数据卷，避免修改宿主机的依赖目录。健康检查改为数据库就绪检查，更新为当前有效的认证参数名。
5. 容器中的首页服务端请求原来使用浏览器的 localhost API 地址，实测返回 500；现在服务端使用 `API_INTERNAL_BASE_URL`，浏览器继续使用公开地址。修复后容器首页返回 200，浏览器请求不会泄漏内部主机名。
6. Web 容器显式监听 `0.0.0.0`；生产 Compose 固定 API 的 production 模式和内部端口，允许覆盖宿主机端口。
7. 本地 Docker 图片优化器无法通过浏览器的 localhost 地址读取上传图片；开发模式由浏览器直接读取图片，并在 CSP 中允许指定的公开 API 图片来源。生产模式仍保留图片优化。
8. 前端的本地和生产环境模板分开，避免复制模板后本地网页连接到示例生产域名。
9. 生产配置检查增加真实 URL 解析、API 路径、TLS、公开 URL 凭据/片段/查询、独立认证密钥、开发默认值和运行参数检查；支持安全读取 dotenv 文件。
10. 新增 `--compose` 检查 Docker 实际解析到的 API 环境及 Web 构建参数，避免终端中的密钥掩盖 API 配置文件空值。不会输出配置内容或密钥。已使用真实 `docker compose config` 验证空值拒绝及完整配置接受。
