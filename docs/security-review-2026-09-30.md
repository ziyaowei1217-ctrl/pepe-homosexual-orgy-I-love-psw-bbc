## Mobile usability and performance

Modal focus now includes textareas/selects and contains keyboard navigation; mobile safe areas and 16 px form text cover portrait, landscape and touch devices. Search dates and read-only conversation controls have regression checks. Messaging coalesces refresh bursts, avoids overlapping polls and stale-history replacement, stops background read receipts, and resumes after a phone returns online. These repairs retain server-owned state and mutation idempotency.

HTTP LAN phone demos cannot rely on `crypto.subtle`, which is restricted to secure contexts. Upload checksums therefore retain Web Crypto when available and lazily load SHA-256 from [noble-hashes](https://github.com/paulmillr/noble-hashes) when unavailable, with known-vector and PNG-equivalence checks. This computes the required checksum; shared/public traffic still requires HTTPS. [Web Crypto secure-context requirement](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/subtle).

Production HTTP loopback previews initially caused WebKit to upgrade CSS requests to HTTPS and lose styling/tap behavior. HTTPS upgrading is now exempted only for HTTP loopback requests; deployed public hosts and HTTPS requests retain it. The browser release gate checks that CSS actually loaded, matching hydration nonces, overflow, uncaught errors and normal filter-dialog clicks. A 200 response alone proved insufficient for this issue.

The production build reports approximately 102 kB of shared first-load JavaScript. Static scripts/styles retain framework caching; per-request nonce documents are dynamic and private. This increases server-rendering work for formerly static pages, a deliberate security/performance tradeoff. No production throughput claim is made from synthetic local browser fixtures. Image validation is bounded, metadata stripping occurs once, conditional image reads avoid storage traffic, and normal modern browsers avoid loading the checksum fallback.

## Residual risks and release prerequisites

1. **Moderate dependency advisory:** Nest 10.4.22 remains affected by [GHSA-36xv-jgw5-4q75](https://github.com/advisories/GHSA-36xv-jgw5-4q75), concerning newline injection in SSE `type`/`id`. The repository has no SSE/EventSource routes; Socket.IO is a different transport. A Nest major migration was deferred to preserve the demo architecture. The audit remains visible; CI blocks high/critical advisories. Reassess before adding SSE and plan a tested supported Nest upgrade.
2. **JavaScript-readable sessions:** Ordinary seven-day bearer credentials still use browser localStorage. Strict CSP reduces injection impact but cannot provide HttpOnly protection or erase the consequences of a compromised same-origin script. Before sensitive public use, define a web BFF/HttpOnly session and CSRF/revocation design; native clients require platform-protected credential storage. The tab-storage admin step-up improvement does not remove this ordinary-token risk.
3. **Existing image objects:** New uploads are sanitized; already finalized objects are unchanged. Inventory old public media, reupload/review, retire raw public objects and purge applicable caches before public use. Previously downloaded photos cannot be recalled. Even sanitized photos can visually reveal location.
4. **Historical generated keys:** Gitleaks 8.30.1 scanned 224 commits and reported 16 candidates: four test-placeholder occurrences and twelve historical generated Next manifests/cache-key occurrences. Current tracked sources exclude `.next` and private env files. No live provider key was confirmed. If deployments used those historical builds, rebuild and rotate their server-action/preview keys and associated credentials; investigate deployment provenance. No Git history rewrite was performed.
5. **Infrastructure:** Apply HTTPS ingress, forwarded-header overwrite and direct-API isolation; keep `TRUSTED_PROXY_HOPS=0` until the actual proxy chain is known. Apply edge rate/connection/body limits, especially to anonymous image traffic and broad write abuse. Validate real Valkey/storage/email/payment integrations, storage CORS, backup restore, monitoring and secret rotation ownership. API images currently retain development tooling for their migration entry point; separating migration/runtime images is a later delivery improvement.
6. **Platform delivery:** The deliverable is a web demo. Store packages, platform identity/session binding, physical-device QA and submission acceptance remain separate work. See [platform delivery](platform-delivery.md) and [demo/operations](demo-and-operations.md).
