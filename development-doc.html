1. 项目概览与技术目标

本项目是一个面向高校学生、留学生、实习生与白领人群的高信任短租/转租平台。核心闭环为：用户认证 -> 室友匹配 -> Group 组队 -> 地图找房 -> 房源确认 -> 定金托管 -> 入住核销 -> 双向评价与信用沉淀。

系统需要同时处理 marketplace 供需撮合、社交匹配、地理搜索、支付托管、合同材料、内容审核与信用风控。正式版采用模块化单体优先，避免早期微服务拆分带来的运维复杂度。

开发原则

先跑通 P0 交易闭环，再扩展推荐、金融收益与高频留存服务。

可靠性目标

支付、退款、信用、审核必须可审计，关键状态变化写入日志与 ledger。

产品目标

降低异地短租的信任成本，提高找室友和找房源的撮合效率。

合规边界

本文档不是法律或金融意见，支付托管上线前必须经过专业复核。

2. 总体架构

架构选择：采用模块化单体 API + 独立 Web 前端。数据库保持单一事实源，异步任务通过 Redis 队列处理。支付状态以 Stripe webhook 为事实输入，但系统内部必须维护自己的 Booking 与 EscrowLedger 状态。

3. 核心业务域

Auth & Verification

邮箱注册、校园/企业邮箱验证码、人工材料审核、认证标签、后台审核流。

Listings

房源创建、租期、地理坐标、分类相册、短视频、补贴、合同承诺、发布审核。

Matching & Groups

租客画像、左/右滑、双向 Match、群聊解锁、Group 固化、群组偏好聚合。

Booking & Escrow

预订、Stripe 支付、资金托管、确认入住、退款、争议、人工客服介入。

Review & Credit

双向盲评、三维评分、信用分重算、低分降权、金牌转租人激励。

Moderation & Risk

媒体审核、虚假房源举报、证据收集、账户处罚、订单冻结、后台审计。

业务规则摘要

规则 实现要求 落地阶段
校园/企业认证 邮箱验证码优先；无邮箱权限走人工材料审核；认证结果写入 Verification。 P0
租期精确到日 入住/搬出日期必填；允许 3-7 天弹性窗口；搜索时按时间窗交叉匹配。 P0
分类相册 媒体归类为卧室、公共客厅、厨房/卫浴、周边环境；首图必须通过质量检查。 P0
双向盲评 双方 14 天内提交；双方提交或截止后同时公开；评分进入信用重算队列。 P0
低分惩罚 信用分低于阈值时降低曝光、提高保证金或限制卡片流展示。 P1
高频生态 假期转租、微仓、拼单外卖、水电拆分作为 P2 独立模块接入 Group。 P2

4. 数据模型草案

数据模型采用 Prisma 管理 schema；涉及地理位置的字段使用 PostGIS 类型并通过 migration/raw SQL 创建空间索引。金额字段统一用最小货币单位整数存储，例如 cents。

模型 核心字段 说明
User id, email, phone, role, status, createdAt 平台统一账号；角色可包含 tenant、lister、landlord、admin。
Verification userId, type, provider, status, evidenceUrl, reviewedBy 校园/企业邮箱认证与人工材料审核结果。
Profile userId, displayName, school, company, bio, lifestyleTags 卡片流和信用展示使用的公开画像。
Listing id, ownerId, title, address, geoPoint, bedrooms, bathrooms, rentCents, status 房源主表；地图查询依赖 geoPoint 与 PostGIS 索引。
ListingMedia listingId, type, category, url, sortOrder, moderationStatus 图片、短视频、审核结果和首图排序。
LeaseTerm listingId, startDate, endDate, flexibleDays, depositCents 租期与押金信息，供时间窗匹配与订单计算。
RoommatePreference userId, budgetMinCents, budgetMaxCents, commuteTargets, habits, petPolicy 租客匹配画像，供卡片流和 Group 推荐读取。
Swipe / Match actorId, targetUserId, direction, matchedAt 左滑/右滑记录；双向右滑生成 Match 并解锁聊天。
Group id, ownerId, name, memberCount, totalBudgetCents, sharedTags, status 合租小队，聚合预算、标签、通勤目标与候选房源。
Booking id, listingId, groupId, tenantId, status, amountCents, moveInDate 交易主状态机，所有资金和退款动作都关联 booking。
PaymentIntent bookingId, stripePaymentIntentId, amountCents, status, connectedAccountId Stripe 支付意图映射，不直接替代内部订单状态。
EscrowLedger bookingId, entryType, amountCents, currency, source, createdAt 资金流水审计表，记录 hold、release、refund、fee、adjustment。
RefundCase bookingId, reason, status, evidenceUrls, decision, resolvedBy 取消、入住日重大缺陷、争议和客服处理。
Review / CreditScore subjectId, reviewerId, dimensions, rating, visibleAt, aggregateScore 盲评和信用分沉淀，支持后续曝光降权与保证金调整。
Report / ModerationCase reporterId, targetType, targetId, reason, evidenceUrls, status 举报、媒体审核、虚假房源、用户处罚与后台审计。

5. API 模块清单

接口前缀建议使用 /api/v1。所有写接口默认要求鉴权；后台接口要求 admin 权限；支付 webhook 只接受 Stripe 签名校验通过的请求。

模块 关键接口 权限与状态变化
Auth POST /auth/register, POST /auth/login, POST /auth/email-code, POST /auth/verify-email 创建用户、发验证码、完成校园/企业邮箱认证。
Verification POST /verifications/manual, GET /admin/verifications, PATCH /admin/verifications/:id 用户提交材料；管理员通过/拒绝，更新认证标签。
Listings POST /listings, PATCH /listings/:id, POST /listings/:id/media, POST /listings/:id/submit 房源从 draft 到 pending_review，再到 published 或 rejected。
Search & Map GET /listings/search, GET /listings/map, GET /commute/estimate 公开读取 published 房源；按日期、预算、设施、地理范围过滤。
Matching GET /matches/feed, POST /swipes, GET /matches 记录左/右滑；双向右滑生成 Match；低信用用户可被降权。
Groups POST /groups, POST /groups/:id/invites, PATCH /groups/:id/preferences, GET /groups/:id/recommendations 创建合租 Group、邀请成员、聚合预算与偏好、推荐整租房源。
Bookings POST /bookings, POST /bookings/:id/confirm, POST /bookings/:id/cancel, POST /bookings/:id/move-in-report 创建订单、确认预订、取消、提交入住日重大缺陷。
Payments POST /payments/intent, POST /payments/webhook/stripe, POST /admin/refunds/:id/resolve 创建 Stripe PaymentIntent；webhook 驱动 funds_held；管理员处理退款。
Reviews POST /reviews, GET /reviews/received, POST /admin/credit/recalculate 提交盲评；14 天规则控制公开；触发信用分重算。
Moderation POST /reports, GET /admin/moderation, PATCH /admin/moderation/:id 举报、媒体审核、冻结房源/订单、处罚用户。

接口设计约定

  • 所有金额字段使用整数最小货币单位，所有时间字段使用 ISO 8601。
  • 状态变化接口必须幂等；支付 webhook 必须记录事件 ID，避免重复处理。
  • 用户端不能直接传入信用分、曝光权重、ledger entry 等系统字段。
  • 后台管理动作必须写入 audit log，包含操作者、目标对象、动作、前后状态。

6. 支付与托管状态机

合规提醒：PRD 中的定金代管、资金沉淀和收益账户设计涉及支付、托管、货币传输和消费者保护风险。工程实现前必须确认 Stripe Connect 模式、平台责任、资金流和当地监管要求。

主流程状态

draft -> pending_payment -> funds_held -> confirmed -> move_in_pending -> completed
状态 进入条件 允许动作
draft 用户选择房源、租期、Group 或单人身份，创建预订草稿。 修改租期、取消草稿、发起支付。
pending_payment 系统创建 Stripe PaymentIntent，等待用户支付。 完成支付、过期关闭、用户取消。
funds_held Stripe webhook 确认支付成功，内部 ledger 记录 hold。 房东/原租客确认、风控冻结、退款申请。
confirmed 供给方确认订单，平台锁定房源对应租期。 进入入住待核销、按规则取消、提交争议。
move_in_pending 到达入住日或入住窗口。 租客确认入住、提交重大缺陷、客服冻结。
completed 入住核销完成，资金释放和服务费入账。 发起盲评、售后举报、查看合同与收据。

异常分支

场景 处理规则 系统记录
取消与退款 P1 实现阶梯规则：入住前 7 天及以上全退，3 天内扣 50%，入住当天取消按规则补偿受损方。 RefundCase + EscrowLedger refund/fee/adjustment。
入住日重大缺陷 租客提交照片证据后订单进入 frozen_review；客服审核后全退、部分退或驳回。 证据 URL、客服决策、冻结时间、最终资金动作。
支付 webhook 重复 用 Stripe event id 做幂等键；重复事件只记录，不重复记账。 webhook event log 与处理结果。
人工客服介入 后台可冻结订单、要求补充证据、执行退款或释放资金。 admin audit log 与 ledger adjustment。

7. 三阶段开发里程碑

阶段 目标 功能范围 验收标准
P0 MVP Launch 跑通“认证 -> 组队 -> 找房 -> 支付托管 -> 入住 -> 评价”的基础闭环。 邮箱认证、房源发布、分类相册、地图找房、租期日历、室友卡片流、Group 创建、基础 Stripe 托管、基础盲评。 真实用户可发布房源、完成 Match/Group、通过地图找到房源、支付定金、订单进入资金托管状态并完成评价。
P1 Scale & FinTech 提升整租大户型消化效率，完善退款风控和信用惩罚，接入服务费分账。 Group 房源推荐、阶梯退款、入住日缺陷保障、低分曝光降权、保证金调整、止损精算器、服务费分账。 Group 推荐可解释；退款和缺陷案例可审计；信用分影响排序；服务费与资金流水对账一致。
P2 Retention Moat 用高频生活服务延长用户生命周期，形成租后留存。 假期快捷转租、共享微仓、Group 拼单外卖、水电费多因子拆分工具。 已成交 Group 可发起二次供给或生活服务；账单拆分可按入住天数和房间权重计算；P2 功能不破坏 P0/P1 交易链路。
